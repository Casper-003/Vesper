# 给 Codex 的执行提示词｜Vesper 本地曲库搜索引擎

请在 Vesper 的当前开发仓库实现首版本地搜索，让用户从已有侧栏输入框找到歌曲，并能把选中的演唱版本加入现有待播队列。交付可运行的改动、自动检查结果和简短的 Windows 人工验收清单。下文从这一行起可以整体作为任务指令。

## 一、从已有工程接入

1. 遵循仓库 `AGENTS.md`。先检查分支、工作区与远端状态，阅读当前分支的 `Vesper_项目记忆.md`、`docs/modules/M02.md`，入队部分查 M03。已知 `Casper-003/search` 上有入口，若已合并或本地有更新，以实际包含入口的工作版本为准，保护未提交改动。
2. 从 `src/Vesper.App/MainWindow.xaml` 中的 `GlobalSearchBox` 定位输入。现有 `MainWindow.SearchEntry.cs` 管理放大镜动画和侧栏行为。`MainWindow.Library.cs` 中的 `QueueSongAsync` 是核对入队路径的起点。先找到曲库有效资料的生成位置、多来源判定、重复文件识别、详情修正的保存点和导航状态对象，再落代码。
3. **用户已定**：统一搜索并分类返回；歌名、艺人、专辑可检索，歌名和艺人支持全拼与首字母；停顿自动搜索且防抖；按相关度排序；遵守既有去重、版本、画质、可用性与手动修正规则；空词清屏、无命中显示“无匹配”、详情返回恢复位置。旧文档的“三种搜索模式”按本次明确要求改为三个同时参与的检索字段。一次输入只产生一个查询，无需预选或回车。
4. **本轮建议采用的工程默认值**见下文，包括首版组合搜索、防抖时长、返回数量和排序元组。集中定义可调参数，在交付记录中区分“设计目标”和“实测结果”。核心逻辑放在适合现有工程的纯 C# 层，WinUI 层只处理输入、调度、结果绑定、导航与操作。中央结果容器已有则复用，缺失则只做足以展示三类结果、选版本和恢复位置的接线。保留侧栏入口及动画，不增设筛选面板，也不扩建艺人页和专辑页。

## 二、索引里保存什么

首版采用**后台构建的本地内存索引**。以一万首为验证规模，先对预计算的紧凑记录匹配并测量，避免先引入搜索服务器或迁移曲库数据库。

| 层次 | 标识及用途 |
| --- | --- |
| 歌曲组 | 同一作品、同一演唱者集合的展示组，保存稳定 GroupId 和子版本 ID。不同歌手唱同一首歌时各有一行。 |
| 演唱版本 | 区分原版 MV、具体场次现场版、伴奏、改编等，保留 VersionId、曲库条目关联、版本标签、加入时间和可用状态。两个版本都叫“现场版”不足以认定相同。 |
| 文件资源与来源 | 同一版本可有不同清晰度。字节相同的文件复用曲库已验证的内容身份，保留多个来源路径。在该版本可用资源内用现有画质比较逻辑选择最高画质，同画质以既有来源优先级和稳定 ID 决胜。 |
| 艺人、专辑 | 优先用已有实体 ID；合作艺人按曲库的署名关系分别可查。缺少专辑 ID 时，用有效专辑名和可信专辑艺人等发行信息作保守归集，不能仅因同名就合并不同艺人的两张专辑。 |

以上是检索视图的逻辑层次，不要求新建四张业务表。优先使用已有分组和版本身份。旧数据只有单曲 ID 时，先将每条映射为稳定的单成员组；有可靠的作品关系、演唱者和版本依据再关联。文件名近似、同长度、同歌手加同标题，均不足以认定两个文件属于同一演唱版本。缺少身份、画质或“原版”证据时保留未知，不能猜测。索引不改写媒体、业务 ID、收藏或队列。

索引以**曲库当前实际显示的有效值**为输入。用户手动改名、改艺人、改专辑或明确清空字段后，搜索同步生效。沿用曲库已有的合法显示回退；显式清空不能被旧缓存、文件名解析或联网旧值填回。索引可读取已保存的有效资料；查询不扫描文件夹、不读取媒体标签、不调用联网补全，也不依赖某一行先滚进视口才可搜索。

## 三、查询与匹配算法

1. **保留显示文本，另生成检索键。** 对资料和输入执行同一规范化流程：Unicode NFKC、大小写折叠、首尾去空格、连续空白折叠。保留字面键，另建简繁统一的比较键和忽略常见分隔符的紧凑键。标点保留在字面匹配中，保证 `C++`、`A-Lin` 这类名字能优先精确命中。归一后为空的附加键不参加匹配。只含空白按空输入处理。
2. **拼音在建索引时算一次。** 为歌名和每个署名艺人生成无声调全拼、逐音节首字母，保留原有拉丁字母和数字。优先复用项目已有、能离线运行的中文转换能力。确需新依赖时先验证目标框架、许可证、离线打包和词组读音。用小型词组覆盖表处理可验证的多音字，如“重庆”的 `chongqing/cq`；避免给每个多音字生成所有排列。专辑首版支持文本匹配。
3. **先试整句，再做组合。** 保留整句尝试标题、艺人、专辑的等值、前缀和连续包含，以免拆散英文歌名。另按空白分出词项，不依赖中文分词器。一个词项可以命中多个字段；组合路径要求每个词项都获得证据。歌曲的跨字段组合限于同一候选演唱版本及其关联的歌名、艺人和专辑。不得从两首歌或两个兄弟版本各取一部分拼成命中。
4. **首版支持乱序和混输。** `周杰伦 稻香`、`稻香 周杰伦`、`zjl dx`、`周杰伦 daoxiang` 用同一套词项规则处理。汉字和拉丁字面词允许精确、前缀和连续包含；完整全拼和至少两个字母的拼音前缀可命中；首字母仅开放长度至少为 2 的等值或前缀。一个拉丁字母仍可查真实文本，例如艺人 A，但不启动全库拼音或首字母召回。首版无需猜测无空格的多个字段怎样切分。
5. **识别版本意图。** 先尝试按整句真实标题匹配。对“稻香 现场版”“稻香 live”这样的独立限定词，从小型映射表解析 `现场版/live`、`伴奏版/伴奏`、`原版MV` 等，和其余词一起核对同一版本。限定词必须有该版本的明确证据。单独搜 `Live` 仍可命中同名作品；曲名内部含有“现场”也不自动拆掉。真实整句标题优先于推断出的版本解释。
6. **三类结果独立召回。** 歌曲可以因艺人或专辑命中。艺人和专辑卡片只在自身名称或署名等该类明确支持的字段覆盖查询时返回。搜“周杰伦”可得到艺人和其曲目；搜“周杰伦 稻香”即使只剩歌曲也正常。没有直接证据时不拿第一首歌的艺人或专辑凑数。

## 四、排序与命中子版本

对每条候选记录最好的**有效匹配路径**，按下表从高到低比较。只在全部词项满足后排序，先按版本评估，再以组内最佳命中的排序键给歌曲组排序。候选入组后才截取首屏。

| 优先级 | 歌曲区规则 |
| --- | --- |
| 1 | 通常先排“歌名和艺人均文本精确”，再排“整个查询精确等于真实歌名”。仅在与推断出的版本解释竞争时，整句真实标题优先。 |
| 2 | 其他仅靠文本精确就能覆盖的匹配，如准确艺人、准确专辑或歌名加专辑。 |
| 3 | 全部用文本命中，但至少一项为前缀；需要连续子串才能覆盖时再降一档。 |
| 4 | 需要全拼才能覆盖。全拼等值优先于全拼前缀。 |
| 5 | 需要首字母才能覆盖。首字母等值优先于前缀。 |

同一候选有多条路径时取最高档。组合匹配由最弱的必要证据定档，例如“周杰伦 dx”不能因艺人精确就得到第一档。**同档依次比较**：文本精确词项数降序 → 命中歌名的词项数降序 → 字面原文优于折叠形式 → 命中字段中多余字符总数升序 → 稳定的规范化歌名、艺人、GroupId 顺序。对同档的全拼／缩写先按表内等值优先规则。艺人／专辑区分别按本类名称的文本精确、前缀、包含、支持的拼音证据及稳定实体 ID 排序。首版不引入收藏或常唱加权；以后若经使用验证需要，只在相关性相同的候选间决胜。可以用元组、比较器或等价可测试的实现。

**分开计算组代表和命中目标**。代表版本从可用版本中优先选有依据的原版 MV，否则选最早入库的可用版本，同日同刻用稳定 ID 决胜。画质只在同一版本内部比较。当组内全部不可用时按曲库隐藏设置处理，若允许显示则保留可辨认的禁用项。

例如库中有周杰伦《稻香》原版 MV 720p、现场版 1080p 和 4K，还有另一位歌手的同名翻唱。裸搜“稻香”返回两个歌手组；周杰伦组以原版 720p 作代表。搜“稻香 现场版”时，周杰伦组仍占一行，保留代表项，结果附“命中：现场版”。按既有分组控件展开时定位到最佳匹配现场版本，可在该子项点歌，解析为可用的 4K 文件。多场现场都命中时保留各自 ID。子项先按命中证据排序，同分时依次选组代表（仅当它也命中）、可用且最早加入的版本、稳定 VersionId。**分组主行只展开，入队命令绑定具体版本 ID。** 若选中版本失效，先在同版本找其他已收录可用来源或较低画质；全部失效则按曲库规则提示，不替换成原版或别人的翻唱。

## 五、结果契约

字段名是示意，优先适配仓库已有类型。引擎返回普通只读数据，不持有 WinUI 控件、文件句柄或播放对象。

| 返回对象 | 最小字段与含义 |
| --- | --- |
| SearchResponse | 原始查询、QueryId、IndexRevision、状态、歌曲／艺人／专辑各自的结果页。成功且三类均空才是 NoMatch。 |
| SongGroupHit | GroupId、有效歌名／艺人、RepresentativeVersionId、BestMatchedVersionId、MatchedVersionIds、有序子项或按组取得子项的方法、是否可用、MatchEvidence。依靠 ID 区分“展示谁”和“正在操作谁”。 |
| VersionHit | VersionId、既有曲库条目 ID、版本名、可用状态、首选可用资源 ID（可空）、画质。入队前用当前曲库复核。 |
| ArtistHit / AlbumHit | 稳定实体键、显示名、必要的区分信息、MatchEvidence；可选本地可见歌曲组数。 |
| MatchEvidence / ResultPage | 前者记录命中的字段、词项、方式及版本 ID。后者提供 Items、HasMore 和绑定查询、类别与索引快照的续页标记。拼音命中可只返回字段说明，不把拼音偏移当汉字高亮位置。 |

建议首批歌曲 **30 组**、艺人和专辑各 **5 项**，各类独立续取，界面可以仅消费最佳艺人和专辑。首版可对同一查询保留一次排序好的 ID 序列，续页只切片；查询被替换后释放。相同输入和同一索引版本，反复搜索和续页应得到相同顺序，无重项、漏项或跨查询接页。

## 六、更新索引与查询调度

- **初始化和更新。** 从曲库一致快照后台建索引，完成后原子发布，只读查询持有固定修订号。首建期间记录并重放快照之后的变动，或检测修订变化后补建，防止旧构建覆盖新资料。首建未完成时使用准备中状态；重建失败时保留上一份可用快照，首次构建失败标记可重试，不显示“无匹配”。
- **增量失效。** 订阅导入、目录移除、重扫、资料保存与清空、结果被曲库接纳的后台补全、版本关系、画质与来源可用性变化。批量变化按稳定 ID 合并；删除旧键再加入新键，同时更新旧组和新组、艺人和专辑的计数与成员。隐藏不可用的偏好改变后重算可见结果。事件缺少细粒度信息时，可合并为一次后台重建。检查增量结果与全量重建一致。
- **输入防抖。** 建议初值 **180 ms**，从最后一次已提交文本变化计时。每次编辑立即递增 QueryId，使旧任务失去发布权，取消旧计时与查询。中文输入法开始组词时同样使旧任务失效，预编辑过程不搜；提交／取消后读取最终文本并去重调度。清空马上清屏并保持在当前搜索上下文，页面离开后废弃待发布结果。IME 选词回车不能触发点歌。
- **避免竞态。** 防抖后捕获查询 ID、搜索会话、索引快照，在后台计算，循环中响应取消。回到 UI 线程真正写入前再次核对会话和 QueryId；索引已换代时丢弃不再适用的结果并合并刷新。迟到的首屏、续页、初始化和导航回调都走同一发布约束。取消令牌是节省工作量的手段，最终写入检查保证正确性。
- **操作稳定。** 同一次提交一次性绑定对应快照，不逐条插入重排。按下结果行、弹出版本选择或执行入队期间，可延迟由后台资料更新引起的重排；操作始终绑定稳定 ID，触发时复核当前可用性。用户自己换词或清空可立即废弃旧会话。每次键入不新增导航历史。
- **详情返回。** 记录原始关键词、当前已载入页、结果锚点 ID 和相对像素偏移。索引未变时复用结果并还原位置；已变时重查并恢复同一锚点，锚点被删则回到最近仍在的相邻行，再回退到列表顶部。程序回填搜索框不能额外发动查询或抢走滚动位置。

## 七、实施顺序与性能验收

| 阶段 | 执行动作 | 完成标志 |
| --- | --- | --- |
| A｜本轮 | 实现有效资料投影、索引、文本与拼音匹配、组合查询、排序、版本命中和三类结果。 | 用构造曲库跑确定性检查，覆盖旧数据、同名同版、子版本和资料修正。 |
| B｜本轮 | 接入已有输入框、中文输入法、防抖、取消、最小中央结果绑定、版本选择、既有入队与返回恢复。 | 从现有入口走通真实操作。已有入口检查若仍断言“输入永不导航”，只更新已经被本任务取代的断言，保留动画、聚焦和布局回归。 |
| C｜本轮 | 接入增量更新，执行并发回归与万首基准。首版扫描预计算键若未达标，先分析耗时，再按瓶颈增设精确／前缀倒排或中文二元片段候选表；继续用同一精排器验证结果。 | 报告设备、构建配置、数据规模、延迟分位数和未覆盖的验证项。 |
| D｜后续评估 | 优先接入有出处的艺人别名；再对较长词、严格召回不足时评估小编辑距离容错。歌词只搜已导入或已缓存文本，单列命中原因，优先级低于元数据。在线曲源以后单独接入，区分可点唱资源与仅歌曲信息，本地结果先独立完成。 | 本次不启动额外联网、歌词索引或个性化排序。已有详情联网补全仍走既有流程。 |

**延迟口径**：180 ms 是防抖建议；300 ms 是“最后一次提交文本变化到首屏真正呈现”的热态参考目标，包含防抖、后台排队、检索、分组排序、UI 调度和绑定。初始给后半段约 120 ms，总目标建议以实测端到端 P95 评估。用约一万首本地测试曲目，含中英混合、短词、常见前缀、多个版本和来源，Release x64、无调试器，预热后混合运行至少 100 次。分别记录引擎耗时和端到端 P50/P95、冷建时间及索引内存增量。不能测真实首屏的环境只报核心耗时，标出 Windows 待测项；禁止把计时器触发、任务返回或各段 P95 相加写成实测首屏。

## 八、必须验证的行为

使用合成曲库，不依赖个人媒体或联网结果。尽量扩展 `tests/Vesper.Core.Checks` 等现有检查；竞态用可控时钟和可人工延迟的查询，不靠随机 sleep。

| 场景 | 期望 |
| --- | --- |
| 查“稻香 / daoxiang / DX / ｄｘ”及“周杰倫” | 前四个输入分别找到同一首目标歌。繁体艺人名找到正确艺人及其曲目。 |
| 查“稻香 周杰伦 / 周杰伦 稻香 / zjl dx / 周杰伦 daoxiang” | 四次均命中同一艺人的《稻香》。另一艺人的《稻香》和周杰伦的其他作品被排除。 |
| 构造标题“稻香”“稻香路”“故乡稻香”，将弱匹配项设为收藏 | 精确标题在前，前缀在连续包含前；收藏不能跨档。字面标题 DX 在仅靠缩写命中的题名之前。 |
| 搜索专辑名；存在不同专辑艺人的同名专辑 | 能返回匹配专辑及其本地曲目，两张专辑身份独立。 |
