# 本地搜索引擎规格

更新：2026-11-04。保存搜索独有的算法、身份与数据契约；交互规则见 [M02](modules/M02.md)，命令见 [开发与调试](开发与调试.md)，实际结果见 [验证记录](验证记录.md)。规格目标不等于真实曲库已完成验收。

## 范围与索引

一次输入同时检索歌名、艺人、专辑并分类返回，无需模式预选或回车，不增设筛选面板。采用后台构建的本地只读内存快照，以万首规模衡量；查询不扫描目录、不读媒体标签、不联网补全、不依赖可见行。Core 返回普通只读数据，不持有 WinUI 控件、文件句柄或播放对象。

| 逻辑层 | 身份、归集与选择规则 |
| --- | --- |
| 歌曲组 | 同一作品、同一演唱者集合，稳定 GroupId 和子版本 ID；不同歌手翻唱各一行。 |
| 演唱版本 | 稳定 VersionId、曲库关联、版本标签、入库时间、可用性；原版、具体场次现场、伴奏、改编分别识别。“现场版”同标签不足以证明同版。 |
| 文件／来源 | 同版不同清晰度；字节相同复用已验证内容身份并保留多个路径。同版本可用资源选最高画质，同画质按既有来源优先级、稳定 ID。 |
| 艺人／专辑 | 优先复用实体 ID，合作艺人按署名分别可查；缺专辑 ID 时按有效专辑名、可信专辑艺人等保守归集，不合并不同艺人的同名专辑。 |

这是检索视图，不要求另建四张业务表。不改媒体、业务 ID、收藏或队列。旧数据仅有 SongId 时用稳定单成员组；文件名近似、同长度、同歌手同标题不足以认定同版本。作品关系、身份、画质、入库时间或“原版”证据不足则保留未知。**当前真实旧库采用该保守回退；核心合成多版本／4K 检查不代表真实端到端已实现。**

输入取曲库当前实际显示的有效值（`SongDetails.Effective`），保留合法显示回退。手动更名／改艺人／改专辑／显式清空同步生效，旧缓存、文件名或晚到网络值不能补回清空字段。全库索引读取已有资料与后台采集资料是独立链路。

## 检索键与匹配

1. 保留显示原文，另生成字面键：Unicode NFKC、大小写折叠、首尾去空格、连续空白折叠；再建简繁统一键和忽略常见分隔符的紧凑键。字面键保留 `C++`、`A-Lin` 等标点，优先原文精确；归一后空键不匹配，空白输入视为空词。
2. 歌名及每位署名艺人的无声调全拼／逐音节首字母在建索引时一次预算，保留拉丁字母与数字；专辑首版仅文本。转换离线运行，小型可验证词组表处理多音字（现有“重庆／长安／音乐”），不穷举读音排列。新增依赖须核对框架、许可、离线打包与词组读音。
3. 先整句尝试标题／艺人／专辑等值、前缀、连续包含，保护英文标题；另按空白分词，不依赖中文分词器，不猜无空格多字段切分。组合要求每个词项有证据，限同一候选版本的关联字段，不能跨歌或跨兄弟版本拼证据。
4. 乱序与混输共用规则：`周杰伦 稻香`、`稻香 周杰伦`、`zjl dx`、`周杰伦 daoxiang` 均命中同一目标。汉字／拉丁字面词支持等值、前缀、连续包含；完整全拼等值和至少两字母的全拼前缀可命中；首字母仅长度≥2 的等值／前缀。单拉丁字母可查真实名称（如 A），不触发全库拼音／缩写泛召回。
5. 整句真实标题优先于推断版本意图；小型映射解析独立的 `现场版/live`、`伴奏版/伴奏`、`原版MV` 等限定词，与其余词核对同一版本明确证据。单独 `Live` 仍可查真实同名作品；曲名内“现场”不自动拆除；互斥兄弟版本不能拼命中。
6. 三类独立召回。歌曲可因艺人／专辑命中，实体卡片必须自身名称／署名等支持字段覆盖查询，不能拿第一首歌的艺人／专辑凑数；`周杰伦 稻香` 只有歌曲结果是正常情况。

## 排序、代表与命中目标

只在全部词项满足后排序；按版本选最佳有效匹配路径，再按组内最佳命中的键排歌曲组，入组后截首屏。组合由最弱的必要证据定档，例如 `周杰伦 dx` 不能因艺人精确就进最高档。

| 从高到低 | 必要证据 |
| --- | --- |
| 1 | 歌名＋艺人文本精确，然后整句精确真实歌名；与推断版本解释竞争时，整句真实标题优先。 |
| 2 | 其余全词项文本精确，如准确艺人／专辑、歌名＋专辑。 |
| 3 | 全文本但至少有前缀；必须连续包含才能覆盖的再降档。 |
| 4 | 必须全拼；等值先于前缀。 |
| 5 | 必须首字母；等值先于前缀。 |

同档依次：文本精确词项数降序→命中歌名词项数降序→字面原文优于折叠形式→命中字段多余字符总数升序→稳定规范化歌名、艺人、GroupId。全拼／缩写先比较其等值／前缀。艺人／专辑按本类文本精确、前缀、包含、支持的拼音证据、稳定实体 ID 排序。首版无收藏／常唱加权；以后只可在相关性相同候选间决胜，须另行使用验证。

**组代表与命中操作对象分别保存。** 代表从可用版本选有依据的原版 MV，否则最早入库可用版本，再以稳定 ID；画质只在同一版本内比较。全不可用按隐藏偏好隐藏或显示可辨认禁用项。

例：同歌手原版 MV 720p、现场版 1080p／4K 为明确同组，另一歌手翻唱独立。裸搜以原版 720p 作代表；限定现场后仍一组、附“命中：现场版”，展开定位最佳现场子项，该版本选可用 4K。多场现场保留各自 ID。子项先比证据，再按组代表（仅当也命中）、可用且最早加入、VersionId。**分组主行只展开，入队绑定具体 VersionId**；失效只回退同版本其他已收录来源／低画质，不能改原版或他人翻唱，全部失效按曲库规则提示。

## 结果与分页契约

字段名可适配既有类型，语义不可混淆：

| 对象 | 最小字段／含义 |
| --- | --- |
| SearchResponse | 原始查询、QueryId、IndexRevision、状态、歌曲／艺人／专辑各自结果页；成功且三类均空才 NoMatch。 |
| SongGroupHit | GroupId、有效歌名／艺人、RepresentativeVersionId、BestMatchedVersionId、MatchedVersionIds、有序子项或取子项方法、可用性、MatchEvidence。 |
| VersionHit | VersionId、既有条目 ID、版本名、可用性、首选可用资源 ID（可空）、画质；入队前复核当前曲库。 |
| ArtistHit／AlbumHit | 稳定实体键、名称、必要区分信息、MatchEvidence；可选本地可见歌曲组数。 |
| MatchEvidence | 命中字段、词项、方式、版本 ID；拼音偏移不能当汉字高亮位置，可仅说明字段。 |
| ResultPage | Items、HasMore，以及绑定查询／类别／索引快照的续页标记。 |

工程默认首批歌曲 30 组、艺人／专辑各 5 项，可独立续取；UI 当前消费最佳艺人、专辑。每查询可保留一次排序好的 ID 序列，续页切片，换词释放。同词／同修订顺序确定，反复查询续页无重项、漏项或跨查询接页。

## 索引、输入和导航的一致性

- 从一致曲库快照后台建索引并原子发布，查询固定修订；首建期间重放变动或检测修订补建，旧构建不覆盖新资料。首建用“准备中”，重建失败保留旧快照，首建失败可重试，不冒充无匹配。
- 导入、移除、重扫、资料保存／清空／接纳后台补全、版本关系、画质、可用性、隐藏偏好均失效。按稳定 ID 合并批变更，删旧键、加新键，更新新旧组／实体成员和计数；缺细事件可合并重建。增量结果须与当前全量一致。
- 防抖默认 180ms，从最后一次提交文本变化起算。每次编辑／IME 开始立即递增 QueryId 并取消旧工作；组词预编辑不查，提交／取消读最终文本去重。清空立即清屏并留搜索上下文，离页废弃发布；选词回车不入队，每次键入不新增历史。
- 防抖后捕获 QueryId、会话、索引快照，后台循环响应取消；UI 真正写入前复核会话／QueryId／修订。迟到首屏、续页、初始化与导航回调同样受约束；取消只节省工作，写入检查保证正确。换代结果丢弃并合并刷新。
- 同次提交一次性绑定快照，不逐条插入重排。按住行、版本弹层或入队时可延迟后台资料重排，操作绑定稳定 ID、执行前复核。主动换词／清空可立即废弃旧会话。
- 返回记录原词、已载页、锚点 ID／相对像素偏移；索引未变复用，否则重查恢复锚点，删除则相邻有效行、再顶部。程序回填输入不重复查询或抢滚动位置。

## 性能目标与待验证边界

300ms 是最后一次提交文本变化到真实首屏呈现的热态参考目标，包含 180ms 防抖、排队、查询／分组排序、UI 调度／绑定，按端到端 P95 评估。万首含中英、短词、常用前缀、多版本／来源，Release x64、无调试器、预热后≥100 次混合查询；分别记录引擎与端到端 P50/P95、冷建时间、内存增量。不能测绘制则仅报核心耗时，不加各段 P95 冒充首屏。**现已测核心，300ms 端到端尚未实测。** 扫描预计算键不足时先剖析，再考虑精确／前缀倒排或中文二元候选，继续共用同一精排器。

现有合成检查覆盖文本／组合／排序、同名专辑、同版副本／画质回退、原版代表／现场命中、Live 真标题、兄弟版本互斥、修正／清空遇晚到补全、离线隐藏恢复、IME 受控竞态、分页返回／稳定对象及首建变更；实际范围与未测项见验证记录。真实 IME、复杂详情链、媒体版本和窗口布局仍须人工核对。

后续再评估有出处的艺人别名、长词严格召回不足时的小编辑距离容错；歌词只索引已导入／缓存文本、单列低于元数据的证据。联网曲源另接，区分可点唱资源与仅资料。本阶段未启动别名／容错、歌词索引或个性化排序；既有详情与全库资料补全沿用各自流程。
