## 协作与交接

身份、分支和工作方式统一见 [AGENTS](../AGENTS.md)。建议发起者负责方向确认、核心开发与合并；协作者从一个可展示的小任务起步，可做参考界面分析、草图、曲目边界样例、体验验收或已确认的小组件。每人同时一个主要任务；卡住时带尝试结果及所需输入沟通。

任务通常放 GitHub Issue；设计结论回写对应模块，具体改动及验证放 PR，不靠聊天全文交接。任务卡使用下面的最小模板：

```text
目标与范围：一个可展示的结果；列明暂不包含内容
负责人 / 模块 / 输入材料：已确认规则、草图或样例链接
交付与验收：文件、截图或 PR；2–4 条可实际检查的条件
状态与下一步：待做 / 进行中 / 等待输入 / 待验收 / 完成
```

收工或换机时留下四行：本次交付（分支/提交/PR）、已检查、当前卡点、下一步。推送成功后另一端须获取对应提交；保存、提交和推送是不同步骤。

## 冲突处理

先用 `git status` 确认当前 merge/rebase/cherry-pick，`git diff --name-only --diff-filter=U` 列出冲突。逐段对照双方已确认需求，移除冲突标记；二进制草图须核对两个版本，设计取舍不明再询问，不整份盲选。

检查差异并运行 `git diff --check` 及本任务必要验证；只 `git add -- <已处理文件>`。无未合并项后按原操作执行 `git commit`、`git rebase --continue` 或 `git cherry-pick --continue`；再有冲突则重复。共享任务分支需要同步时，先保存本任务改动，再 `git fetch origin`、`git merge origin/main`，不强推覆盖历史。
