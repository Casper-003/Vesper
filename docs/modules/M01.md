更新：2026-11-04。主页面竖向、页内详情横向及按原边恢复轴的历史导航已完成，Create 既有侧栏 Suppress 和其他动画保留。最终 Debug／Release x64 编译与 705 项组合回归通过（概览 528＋互动 177，0 失败），25 组路由轴检查正确，新版已正常启动。像素捕获确认了 2 组横向中间过程，3 组竖向未捕获中间 marker，整体方向像素仍不可判定；实际观感与真实键鼠待用户验收。

## 已确认

- 左侧功能栏竖向排列，可折叠、展开；中央为首页内容，右侧队列默认收起，可展开/收起。

- 后退返回已浏览页面时，保留并恢复该页面之前的搜索词和滚动位置。
- 浏览与远距离演唱分别考虑字号和信息密度。

### 浏览历史与原生导航

- 仅记录页面之间的跳转：通过左侧导航进入其他页面，以及进入歌曲详情、艺人详情，均计入浏览历史。
- 展开或收起队列、打开或关闭弹窗，以及进入或返回演唱，不计入这套浏览历史。
- 例如从首页进入艺人详情，再进入歌曲详情，后退时依次返回艺人详情、首页，并恢复各页面之前的搜索词和滚动位置；中途展开队列不会增加一次后退。
- 由原生 Frame 管理后退、前进栈；后退后可前进回原页面，此时打开新页面会清除原有前进路线。例如首页 → 艺人 A → 歌曲 B，后退回艺人 A 后打开歌曲 C，路线变为首页 → 艺人 A → 歌曲 C，不再前进到歌曲 B。
- 2026-11-04 用户在此前全部横移后进一步明确“大页面切换竖向，大页面内的小页面切换横向”。首页、收藏、曲库、创作、设置以及搜索均按主页面处理，主页面之间使用竖向切换；从浏览页进入歌曲、艺人、专辑详情，以及这些详情之间继续浏览，使用横向切换。最新规则直接取代上一轮所有页面统一横移的设计。
- 前进／后退按原跳转边的类别使用对应轴，不把整个历史固定为横向。例如“曲库 → 搜索”为主页面边，“搜索 → 歌曲详情 → 艺人详情”为详情边，返回和前进时分别恢复相应类别；保留原生历史、搜索词、滚动位置和按钮可用状态。
- Create 继续保留既有左侧导航 Selection 进出的 Suppress 特例；其他页头上卷、图片缩小淡出、同色补底、侧栏／队列、图标及操作反馈动画沿用原规则。此轮仅修订导航的主／子页面轴，不以重置页面状态代替切换。
- 当前实现复用同一个官方 `SlideNavigationTransitionInfo`：新导航按目标请求是否含 `SongId`／`EntityId` 选择横向 `FromRight`，其余主页面选择竖向 `FromBottom`。Create 的 Suppress 仍仅用于既有侧栏进出条件。
- 每个 `ShellPage` 保存不可变导航请求。Back 根据离开页面原请求恢复其 incoming 边的轴，再由原生 Back 模式反向；Forward 读取 `ForwardStack.Last()` 目标请求，在无参 `GoForward` 前设置同一共享 Slide 的 Effect。只读取原生栈，不手工增删或重建历史。
- 最终 Debug／Release x64 编译与 705 项组合回归通过，25 组 RouteSamples 正确，覆盖重复 song key 的混合轴连续 Back／Forward、详情转侧栏／搜索、Create 例外、重复选择及新导航清空 Forward。RTB 确认 detail-new／forward-detail 两组横向中间移动，3 组竖向仅能定位终点，整体方向像素仍为 Inconclusive；实际观感与真实曲库键鼠待用户验收。旧 579 项保留上一轮范围，详见[本地实体详情调试](../本地实体详情调试.md)。
- 不因重复选中当前页而创建额外历史。当前复用已有页面内容与歌曲行，保留曲库浏览位置与状态；搜索词恢复仍随完整搜索页后续实现，不声称已完成。
- 页面历史范围于 2026-10-28 确认，前进恢复和固定按钮呈现以 2026-10-29 用户最新方案为准。

### 首页内容

- 整体大方、简洁，保留充分留白。
- 首页按歌手或乐队/组合分类的大封面、推荐、收藏组织内容。
- 每个内容区采用一个标题、一行封面的布局；推荐与收藏的封面比歌手或乐队/组合分类的封面小一些。
- 歌曲封面点击后进入详情页，详情布局归 M02。
- 首页歌手或乐队/组合分类的大封面点击后，统一进入对应的艺人详情页，与歌曲列表中点击艺人名字的去向一致。确认日期：2026-10-28；理由为保持同一艺人在不同入口的浏览体验一致。艺人页内容与具体交互归 M02。
- 首页艺人卡片遵循外部艺人卡片优先显示 Logo 的规则：有可用 Logo 时优先使用 Logo；没有 Logo 时改用艺人照片，个人歌手用头像，乐队或组合用合照；照片也没有时，使用下文已确认的名称占位封面。确认日期：2026-10-28；理由为优先以 Logo 作为卡片的识别形象，并在缺少 Logo 或照片时保持可辨认的入口。乐队在艺人详情页顶部显示合照，与外部卡片分别处理，详见 [M02](M02.md)。
- 一行内容过多时采用横向列表，仅通过点击左右交互按钮浏览，不使用鼠标滚轮进行横向切换。
- 每个分类的封面始终保持一行；多个内容区使整页内容超过窗口高度时，使用鼠标滚轮纵向浏览整个页面。
- 窗口缩窄时保持封面大小，优先减少每行同时可见的封面数量，其余内容通过左右按钮浏览，不换行；维持歌手或组合大封面、推荐与收藏较小封面的层次。确认日期：2026-10-28；理由为保留封面的辨识度和大小层次。
- 收藏为空时不显示首页的收藏栏。
- 歌手或组合区、推荐区也采用同一空内容规则：没有可展示内容时隐藏整个区块，包括标题和占用的空间；首页仅排列其余有内容的区块。曲库为空时，按下文规则提示用户前往曲库页导入歌曲。空区块隐藏规则确认日期：2026-10-28；理由为与收藏栏保持一致，避免空区块占用首页空间。
- 有内容但缺少封面图片时，保留卡片的位置、大小和点击入口，使用统一风格的占位封面，在其中显示对应艺人名或歌名；例如艺人没有照片时，仍保留带艺人名的大封面卡片，点击进入艺人详情。确认日期：2026-10-28；理由为保持首页布局稳定，并允许辨认和进入对应内容。
- 首页不设置导入按钮，也不直接打开目录选择器。没有可用歌曲时，以醒目的图形、大号标题与清楚的分步文字，引导用户先打开左侧“曲库”，再点击右上角的文件夹加号选择本地歌曲或 MV 目录，并说明文件保留在原位置、导入后可浏览、收藏和加入待播。2026-10-29 用户修订：此前单行小字提示确实存在，但字号太小、指引不明确；本轮采用 28 单位标题、16 单位说明与操作步骤，具体效果待用户检查。
- 首版推荐区从当前可用的本地歌曲中随机挑选一组，点击封面仍进入歌曲详情页。确认日期：2026-10-28；理由为提供随意浏览、找歌唱的入口，刚导入曲库且没有演唱记录时也能展示推荐。
- 每次启动生成一组推荐，同一次运行中保持稳定；进入详情页或切换页面后返回首页，仍保留原组；下次启动再换一组。如果启动时曲库为空，就在导入歌曲后首次生成。确认日期：2026-10-28；理由为返回首页时能找回刚才浏览的推荐，并在下次启动时提供新一组歌曲。
