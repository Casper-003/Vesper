# 本地搜索实现与调试

搜索阶段记录：2026-11-03，原工作分支为 `Casper-003/search`，已通过 PR #7 合入 `main`。本报告区分该阶段的数据检查、核心性能测量与待人工验收的 Windows 界面行为；后续详情页及整库资料采集在 `Casper-003/entity-details` 接续，见[本地实体详情调试](本地实体详情调试.md)。

## 本轮接入范围

已有侧栏搜索框现在连接本地内存索引。一次输入同时检索歌名、艺人、专辑，不要求先选择模式；结果分类返回。中央页沿用上方艺人／专辑、下方歌曲的结构；界面当前消费最佳艺人和最佳专辑，歌曲首批 30 组并可继续加载。核心默认返回艺人、专辑各 5 项，保留各类别独立续页能力。

输入采用集中定义的 180ms 防抖默认值，支持中文输入法组词期间暂停查询、提交后调度、旧查询失效与页面离开后的发布检查。180ms 是工程默认值，不代表整体首屏响应已经达到性能目标。搜索框清空后清除结果并留在搜索页；非空查询成功且三类均空时才显示“无匹配”。准备中、构建失败和重试分别处理。

本轮不增加筛选面板，不扩建艺人／专辑详情页，不启动歌词索引、别名扩展、容错或个性化加权。已有歌曲详情中的联网补全继续沿用原流程，搜索查询本身不读取媒体标签、不扫描目录、不发起联网补全。

投影直接复用 [SongDetails.Effective](../src/Vesper.Core/SongDetails.cs) 对歌名、艺人、专辑的有效值，保持与当前曲库显示一致。手动清空艺人／专辑不会从旧缓存、文件名或联网值补回。合法歌名回退继续使用原曲库规则。索引不依赖行先滚入视口，也不改写媒体、曲库 ID、收藏或队列。

2026-11-04 补充边界：上述“索引不依赖可见行”只说明会读取全库已存资料；原先标签由可见行读取、联网资料由打开详情触发，不能据此认为资料获取已覆盖全库。现已新增独立本地／联网后台队列，从空资料曲库自动采集并推动索引更新；273 项 Core／VM 检查包含“不开详情、不滚动 → 自动补全 → 艺人／专辑可搜 → 重启复用”。搜索查询本身仍不发起网络或媒体扫描，真实曲库识别覆盖及新后台状态仪表待人工验收。

入队复用 `MainWindow.Library.cs` 中的 [QueueSongAsync](../src/Vesper.App/MainWindow.Library.cs)。搜索桥接先按明确选中的 `VersionId` 核对其资源和当前 `LibrarySongItem`，再走既有重复点歌提示及入队反馈，普通点歌追加队尾，不改变正在演唱的状态。不会把失效现场版本悄悄替换为原版或其他歌手的翻唱。

当前持久化曲库只有可靠的单曲／内容身份和来源记录，尚无可信作品组、演唱版本、画质排序及入库时间元数据供搜索投影使用。因此真实旧数据按 `SongId` 映射稳定单成员组，未知保持未知，不凭标题、艺人或近似文件名自动认定同版。核心已经支持显式提供的分组、版本和画质身份，并用合成数据验证；不能据此声称真实曲库多版本 4K 选曲已完成端到端验收。

## 匹配与版本选择示例

- “稻香”“daoxiang”“DX”“ｄｘ”可召回同一目标；“周杰倫”可查到对应艺人及歌曲。`周杰伦 稻香`、`稻香 周杰伦`、`zjl dx`、`周杰伦 daoxiang` 要求全部词项在同一候选版本内取得证据。多词查询不会先拼接成一串缩写绕过逐词核对。
- 先尝试整句真实文本，再尝试空白分词组合；单个拉丁字母仍可查真实名称，但不启动全库拼音或首字母召回。`C++`、`A-Lin` 的字面匹配保留标点。
- 排序通常先比较歌名＋艺人文本精确、整句真实歌名、其他文本精确、文本前缀、文本包含，再比较全拼和首字母。全拼／首字母等值各自优先于前缀。组合匹配由最弱的必要证据定档，同档用精确词项数、歌名命中数、字面原文、额外字符数和稳定名称／ID 决胜，不加收藏或常唱权重。
- 合成例中，周杰伦《稻香》原版 MV 720p 与现场版 1080p／4K 属于已明确的同一作品组，另一艺人的同名翻唱另成组。裸搜“稻香”仍以原版 720p 作组代表；搜“稻香 现场版”保留代表并定位现场子项，该版本优先资源为可用 4K。4K 失效可回退同现场版本的 1080p；无可用原版时才选最早加入的可用版本。
- 真正名为“稻香 现场版”的整句标题优先于推断出的版本解释；单独名为 `Live` 的作品可正常查到。不能从两个兄弟版本分别取“现场”和“伴奏”证据拼出命中。只因歌曲命中，不会补造无证据的艺人／专辑卡片。

核心检查覆盖简繁与全半角、拼音／缩写、乱序混输、逐词约束、分类独立召回、排序、明确与未知版本身份、同版多来源和画质回退、分类续页、取消、人工延迟的旧查询、首次构建及重建期间修正、失败保留旧快照与重试、显式清空、滚动中资料变化、来源离线／恢复及隐藏偏好。竞态使用受控完成信号，不用随机延时猜测任务先后。

独立控件回归使用新建的合成曲库并禁用偏好写入，不读个人媒体。导航返回检查走“搜索 → 首页 → 后退”的共享 Frame 恢复路径，没有打开真实歌曲详情，以避免触发已有自动联网资料／歌词流程。显式可信的合成双版本结果还通过原生按钮打开版本弹层、聚焦现场子项并调用其加入按钮，核对进入现有队列的是该现场版本 ID。回调模拟验证离页后的 IME 结束与交互结束任务不能重新拉回搜索；实际 IME 候选操作仍未测试。

既有大窗口短列表回归最初请求 1600×1400，但运行环境将窗口限制为 1300×820，实际列表视口 697，七首加页头需 733，原“七首必能单页放下”的测试前提不成立。仅修正隔离测试：先还原窗口、等待并记录真实尺寸，依据独立测量的页头和行高选取能放下的六首，再保留原滚动高度、偏移归零与滚动条断言；另保留两首缩短列表检查。最终均通过，七首大窗口场景仍未实测，未修改生产列表布局。日志为 `logs/search-overview-regression.json`。

## 万首基准

本机报告保存于 `logs/search-benchmark-release-x64.json`，该日志目录不入库；测试方法和生成数据均在 [SearchChecks.cs](../tests/Vesper.Core.Checks/SearchChecks.cs) 中，可用上述参数重现。以下是一次顺序独立运行的实测结果，并非承诺任何设备都达到相同耗时。

| 测量项 | 实测 |
| --- | --- |
| 配置 | Release，X64，.NET 10.0.14，无调试器 |
| 系统／处理器 | Windows 10.0.26300；AMD64 Family 25 Model 33 Stepping 2，12 个逻辑处理器 |
| 数据规模 | 10000 个合成曲库条目、5000 个明确作品组，含中英混合、短词、多版本和多来源 |
| 运行次数 | 24 次预热后，120 次混合查询；12 类输入各 10 次 |
| 冷建索引 | 1281.717ms |
| 索引保留的托管内存增量 | 51887776 字节，约 49.48MiB；含本次首次加载的离线转换数据，不是进程总内存 |
| 核心查询 P50／P95 | 8.646ms／36.085ms |
| 常见前缀“共同”的 P50／P95 | 37.086ms／48.804ms |
| 单字母 `d` 的 P50／P95 | 4.674ms／8.460ms |
| 双字母 `co` 的 P50／P95 | 3.699ms／10.344ms |

本次测量包含核心查询、分组排序及首批响应生成，不包含 180ms 防抖、UI 排队、绑定、绘制和实际首屏出现。300ms 是“最后一次提交文本变化到首屏真正呈现”的热态端到端参考目标，该项 P50／P95 尚未实测；不能把核心耗时加防抖，或相加各段 P95，写成已测端到端结果。真实磁盘媒体 IO、实际中文 IME 候选、物理键鼠与真实播放不在合成核心基准范围。

## Windows 人工复核清单

1. 展开／收起侧栏后输入真实已收录曲目的歌名、全拼、首字母及“艺人 歌名”组合，确认防抖后的结果正确，原放大镜动画及聚焦正常；单独聚焦搜索框不切页。
2. 用中文输入法连续选字、提交、撤销候选及快速换词，确认组词期间不反复刷新，选词回车不点歌，旧结果不覆盖新词；清空后留搜索页且不出现旧结果。
3. 歌曲列表加载第二批并滚到中间，进入真实歌曲详情再后退；随后修改资料或移除锚点歌曲再返回，核对关键词、已加载范围及可用的相邻位置恢复。真实详情可能沿用已有联网补全。
4. 搜索入队、重复点歌并取消／确认，确认操作绑定选中的歌曲或明确演唱版本、队尾顺序及既有提示，正在演唱的状态保持；若真实库暂无可信多版本关系，不将核心合成 4K 例子当作已验收。
5. 搜索中修改歌名／艺人并清空专辑、刷新或增删目录、切换隐藏不可用偏好；核对索引跟随有效资料，旧值不复现，离线来源恢复后状态正确，前台仍可操作。
6. 窄窗口及展开右侧队列时检查卡片、列表、续页和版本弹层的布局；按住结果行或打开版本弹层时让后台资料更新，确认对象不串行、操作结束后刷新合理。另用实际输入到首屏绘制的统一计时口径测端到端延迟。
