# 概览页滚动后返回的补底异常

日期：2026-11-04。分支：`Casper-003/entity-details`。共享页头／补底同步修复已完成，Debug／Release x64 编译及最终 528 项隔离原生控件导航检查通过；新版已正常启动，实际窗口观感待用户检查。

## 用户反馈与现象

- 用户先在曲库向下滚动，使页头标题和工具栏进入紧凑状态；离开曲库再返回后，标题和工具栏仍紧凑，强调色背景却看起来恢复到展开页头高度，歌曲行叠在该色块区域上。
- [修改前用户反馈截图](../pics/M02-overview-return-backdrop.feedback.png)按原样保存，展示问题状态，不代表当前修复效果或验收通过。
- 截图能够说明标题／工具栏和可见背景状态不一致，不能单凭截图断定是原页头、独立补底层、裁切引用或其他生命周期环节造成。

## 旧版基线与定位依据

- 旧版专用隔离原生控件导航回归执行 379 项检查，其中 26 项失败。曲库、收藏在部分收缩／完全收缩后，经其他概览页再返回时，`x=8, y=64` 或随当前页头计算的下方采样点被强调色染色；同一场景的滚动位置和紧凑标题仍保留。
- 基线支持将问题定位到共享补底裁切与页面滚动状态不同步，而非以重置列表位置解决。修复关注原页头裁切表达式、独立补底的链式依赖和重挂载后的缓存／绑定生命周期。
- 不把这一结果写成“WinUI 重新挂载必然清空 Visual.Clip”；目前没有足够依据保证这种内部行为。旧版基线证明了可见错误及共同机制的失同步范围，不替代修复版对照。

## 已有要求与修复边界

- 返回页面继续保留原浏览位置及对应页头收缩进度，不能以重置滚动到顶部掩盖问题。
- 保留展开页头约占可用高度 0.382、系统强调色、原压暗效果、连续收缩标题、圆角裁切和原有列表位置。收缩后强调色区域应与精简页头一致，不扩展到普通歌曲列表区域。
- 保留用户已确认的普通切页上滑及同色补底：Frame 后方的补色仅填补切页露出的区域，跟随当前概览页的页头高度与滚动裁切，非概览页隐藏；不通过删除补底或停用切页动画修复。
- 共享机制需覆盖曲库、收藏、艺人、专辑、首页与 Create。Create 既有左侧导航进出 Suppress 例外及侧栏动画保留；其前进／后退入口单独验证，不沿用以前 A 组人工反馈当作本轮通过。
- 页头无须滚动的短内容仍按原规则禁止滚动，不人为补空白滚动距离；艺人／专辑页已有长标题换行、图片缩小淡出和精简栏单行规则保留。

## 当前修复实现边界

- 独立 `OverviewBackdrop` 继续使用自己的 `InsetClip`，裁切直接引用当前 `OverviewMotion.Scroll` 和 `Metrics`：下缘收缩量为 `Clamp(-scroll.Translation.Y, 0, metrics.Height - 48)`，不再经原页头 `Visual.Clip` 读取另一条动画表达式的结果。
- 补底缓存当前 motion 身份，替代旧的 sourceClip 身份缓存，使重新挂载后能核对并更新当前页面的滚动／度量引用。
- `OverviewMotion` 持有原页头裁切对象的强引用，并在重新挂载时核对、恢复对应对象；Loaded 时重新获取当前 Viewer 和滚动属性集，重新绑定页头、标题、图片及副标题等表达式。
- 这些调整同步页头与补底的显示状态，不调用 `ChangeView` 把页面重置到顶部，不删除原生切页上滑、同色补底或 Create 的既有导航例外；已通过旧版同矩阵对照及最终扩展回归。
