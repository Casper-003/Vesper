# 创作页切换闪白排查

更新：2026-11-02。修复分支：`Casper-003/fix-create-white-flash`，起点 `c1bad39`。用户人工检查 A 组后反馈“不闪了”，明确要求保留该效果并推送；现已将 A 组行为作为默认实现。

## 排查依据与结果

- 用户反馈：四页统一系统强调色后，进入和离开 Create 均会闪白。
- 当前使用 Windows App SDK `1.8.260921001`；对应 WinUI 1.8.12 的原生 Entrance 切页会先淡出旧页，再让新页移入。项目的透明页面存在露出父卡片底色的条件；Create 进出同时有 220ms 的侧栏占位宽度动画，二者交互尚未验证。
- 官方依据：[页面切换文档](https://learn.microsoft.com/en-us/windows/apps/develop/motion/page-transitions)、[WinUI 1.8.12 Entrance 源码](https://github.com/microsoft/microsoft-ui-xaml/blob/winui3/release/1.8.12/dxaml/phone/lib/ThemeTransitions.cpp#L3141)。有默认动画参与不等于已经确认微软缺陷。
- A 组仅对左侧导航进入或离开 Create 停用原生切页，保留原侧栏动画；用户在实际窗口确认不闪并接受这个效果。该结果支持去除原生切页叠加的处理，但不将其升级为已确认的微软渲染 Bug。B 组固定侧栏占位的对照未执行。

## 最终行为

- `OnSelectionChanged` 在导航之前判断来源或目标是否为“创作”；符合时使用 `SuppressNavigationTransitionInfo`，其他页面继续使用原 `EntranceNavigationTransitionInfo`。
- Create 侧栏仍按原 220ms 宽度动画退场和恢复；页头配色、标题与滚动动画、队列内容及裁切逻辑均未修改。
- A／B 环境开关、排查窗口标题和固定侧栏占位逻辑均移除，普通启动即可获得用户已确认的 A 组效果。
- 前进／后退处理沿用原实现，未纳入这次左侧导航对照或人工验收，不声称已覆盖这些入口。

## 验证

- 用户实际窗口验收：A 组反馈“不闪了，处理得很好”，并明确要求推送。
- 默认实现的 Debug／x64 编译、差异检查及与已验收 A 组的代码等价性复核通过；无排查环境开关或窗口标签残留。不以编译通过替代未检查入口的视觉验收。
