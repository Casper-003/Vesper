# M08 音频与演唱控制

更新：2026-11-06。用户将当前界面收敛为共享低延迟／独占两种模式；即时干声返听已接入，低延迟听感与稳定性仍待设备验收。

## 已确认

- 2026-11-06 最新要求：界面提供共享低延迟／独占两种 WASAPI 模式，独占说明用法。此前的三模式方向由本条更新，兼容共享不再单列。
- 目标支持普通 USB 麦克风＋板载声卡，不以专业 ASIO 声卡或额外第三方驱动为前提。
- 支持范围与总往返延迟实测，10–18ms 不是所有设备的保证。
- 开发顺序先跑通本地点歌／MV 播放，再验证软件返听／处理；首轮验收聚焦导入、找歌、入队、播放，不以麦克风／音效／低延迟为通过条件。该顺序不取消三种模式，也未定稿返听、混响、录音范围。

## 即时人声返听施工（2026-11-06）

- 用户本轮要求新建功能分支施工即时返听，明确目的是唱歌的人实时听见自己的声音，输出可为耳机或音箱。分支 `Casper-003/live-monitoring` 从已合并各功能的 `main`（`43a5a24`）建立。
- 依原存档 3.3 节的技术方向，直接使用 WASAPI。共享低延迟以 `IAudioClient3.GetSharedModeEnginePeriod` 选择合法最小周期，再 `InitializeSharedAudioStream` 建立事件驱动输入／输出；RAW 经 `SetClientProperties` 设置。独占用 `IsFormatSupported` 协商 PCM 格式、`GetDevicePeriod` 获取最小周期，按事件驱动独占初始化；缓冲不对齐时依返回帧数重建客户端。失败明确显示，不静默切模式。
- 设置页提供麦克风／人声输出设备、共享低延迟／独占、开关和音量；初始关闭、音量 20%，仅手动开启后采集。切换设备／模式先停止，再手动开启；不随系统默认设备变更偷偷更换输出。普通选歌／演唱往返不重建共享返听，窗口关闭释放。
- 独立 MTA 音频线程、MMCSS、预分配有界人声环形缓冲、44.1k／48k 等格式转换及水位反馈速率微调；欠载静音、超量丢弃过期人声，不无限积累延迟。该插值／水位策略属于首轮实现，需真实双设备长测，不能据合成检查宣称音质或稳定性已验收。无录音、混响或人声分离。
- 共享低延迟首包到达即送出，不再等两周期蓄水，也不把输出缓冲全部空位预填静音／人声；共享输出排队最多一个周期。速率微调以约 1ms 水位余量吸收独立时钟差，不以余量作为共享启动门槛。独占必须整包写硬件缓冲，首次准备一个输出包及一个采集包的余量，避免不同硬件周期相位交错造成周期性缺帧；此处使用实际探测的小周期，不固定成 10ms。捕获落后时丢弃过期数据；硬件周期不可凭代码消除。
- 独占当前用于干声返听对照，尚未接伴奏统一输出。选项下持续说明：独占所选输入／输出、先停止其他播放／录音、不支持时显示错误；现有预览或演唱未结束时拒绝开启独占。开始歌曲预览／演唱前会停止并等待独占设备释放，提示同时播放伴奏与返听请选择共享低延迟；不让 MediaPlayer 在设备仍被独占时直接失败。
- 爆音处理分开验证：开启／调音量有幅度渐变，用户关闭前做有界短淡出；采集中断、过期数据丢弃或输出缺帧后用约 2ms 交叉渐变抑制不连续。没有新增前瞻音频队列；状态显示采集中断／输出缺帧计数。缓冲策略、硬件削波、实际设备调度仍可能造成噪声，不把合成检查记成爆音已消除。总延迟仍需实测，界面周期不是总延迟。
- 旧技术记录出处：Git `baf872e^:docs/archive/项目记忆-2026-10-27.md` 第 3.3 节。官方接口：[周期探测](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient3-getsharedmodeengineperiod)、[共享流初始化](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient3-initializesharedaudiostream)。验证结果归 [验证记录](../验证记录.md)。

## 后续待讨论与验证

- 主界面／演唱画面直接放哪些人声与伴奏控制，哪些入设置；返听、混响等首版范围、文案、默认值。
- 当前默认共享低延迟，切换先停止再手动开启；自动扩大周期、失败恢复／回退仍未接入，不默认增加延迟掩盖欠载。
- 首轮已选择原生 WASAPI 互操作及设备周期探测；跨设备速率微调需实测，独占混音、录音对齐及高级处理尚未实现。后续继续核验 RAW、实时线程、时钟漂移等官方工程边界，按需入口见 [开发与调试](../开发与调试.md)。
- 建议先讨论演唱中最需直接调节的两三个控制及入口，将界面讨论与底层验证分开。
