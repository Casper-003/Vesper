# 开发与调试

更新：2026-11-04。按任务查命令与源码；当前产品规则见所属模块，既有检查结果和人工验收边界见 [验证记录](验证记录.md)。本文件不表示本次已重新执行构建。

## 环境、构建与启动

Windows、.NET 10 SDK、Visual Studio 的 WinUI C# 支持。`global.json` 从 10.0.100 向最新 feature band 滚动；已用环境为 SDK 10.0.403、VS 2026 Community。实际依赖版本以 csproj 为准：Windows App SDK 1.8.260921001，应用仅 x64、非打包、自包含。

以下从仓库根目录运行，VS 路径按安装位置调整。新环境首次还原 NuGet；避免 IDE 与命令行同时构建同一输出目录。

```powershell
$vesperMsBuild = 'C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe'
& $vesperMsBuild Vesper.slnx /restore /p:Configuration=Debug /p:Platform=x64 /m:1 /nr:false /v:minimal
& $vesperMsBuild Vesper.slnx /p:Configuration=Release /p:Platform=x64 /m:1 /nr:false /v:minimal

dotnet build tests/Vesper.Core.Checks -c Release --no-restore /nr:false /v:minimal
dotnet tests/Vesper.Core.Checks/bin/Release/net10.0/Vesper.Core.Checks.dll
dotnet tests/Vesper.Core.Checks/bin/Release/net10.0/Vesper.Core.Checks.dll --search-benchmark

& .\src\Vesper.App\bin\x64\Debug\net10.0-windows10.0.19041.0\win-x64\Vesper.App.exe
```

也可 `dotnet build src/Vesper.App/Vesper.App.csproj -c Debug -p:Platform=x64`。VS 打开 `Vesper.slnx`，选 `Debug | x64`，将 Vesper.App 设为启动项目，使用 `Vesper (Unpackaged)` 按 F5。修改过解决方案平台映射后重新打开解决方案；Git 小锁图标不代表源码只读。直接运行 Release EXE 时，将上面产物路径的 Debug 换为 Release；构建配置与是否附加调试器分别记录，冷启动与预热分别比较。

文件占用时先停止构建／调试并关闭旧 Vesper；必要时正常关闭残留编译服务：

```powershell
dotnet build-server shutdown --vbcscompiler --msbuild
```

曾有 VBCSCompiler 占用 Core/XAML 中间 DLL、PRI 文件；串行且临时加 `/p:UseSharedCompilation=false` 可用于排查，默认配置随后也构建成功，未把规避参数固化进工程。NuGet 首次还原曾约三分钟、再次仅 2.02 秒，未确定最初慢点；不要据“正在还原”推断缺 SDK，也不应直接清空全部包缓存。

## 隔离检查与性能记录

常规界面由用户操作。下列为现有原生控件专项回归，使用合成数据、不解码个人媒体，不代替真实键鼠或视觉验收。每次只设置一个 `*_CHECK_PATH`，提供绝对报告文件路径；检查结束自动关闭窗口。报告和派生 store 放在忽略目录。

```powershell
$vesperExe = Join-Path (Get-Location) 'src\Vesper.App\bin\x64\Debug\net10.0-windows10.0.19041.0\win-x64\Vesper.App.exe'
New-Item -ItemType Directory -Path local-data\diagnostics -Force | Out-Null
$env:VESPER_NAVIGATION_CHECK_PATH = Join-Path (Get-Location) 'local-data\diagnostics\navigation.json'
try {
    Start-Process -FilePath $vesperExe -WindowStyle Hidden -Wait
} finally {
    Remove-Item Env:VESPER_NAVIGATION_CHECK_PATH
}
```

| 环境变量 | 对应入口／范围 |
| --- | --- |
| `VESPER_NAVIGATION_CHECK_PATH` | `MainWindow.OverviewNavigationRunner.cs`：概览＋互动组合矩阵；另设 `VESPER_NAVIGATION_CHECK_SCOPE=interactions` 只跑互动，结束后同样清除 scope。 |
| `VESPER_SEARCH_CHECK_PATH` | `MainWindow.SearchChecks.cs`：输入调度、分类结果、分页、Frame 恢复和显式合成版本入队。 |
| `VESPER_QUEUE_CHECK_PATH` | `MainWindow.QueueChecks.cs`：队列开合、实际内容绘制／命中、拖动状态与按钮调用。 |
| `VESPER_RUNTIME_CHECK_PATH` | `MainWindow.RuntimeChecks.cs`：千行虚拟化、底色／高亮状态、布局、搜索入口和补底。 |
| `VESPER_PERF_TRACE_PATH` | `UiResponsivenessTrace.cs`：普通预览的可选本地诊断；每 32ms 采 Dispatcher 排队延迟，每五秒输出峰值／P95、50/100ms 次数、GC、CPU、容器／排序数据、限长 JSONL 与最近 64 次长停顿上下文，不含曲名／媒体路径、不联网。它不是渲染帧时间。 |
| `VESPER_PREVIEW_PAGE=曲库` 或 `收藏`；`VESPER_PREVIEW_QUEUE=1` | 普通预览直接显示指定页面／展开队列；使用真实本机曲库，结束后清除变量，常规启动仍从首页和收起队列开始。 |

检查路径／预览变量只作用于当前进程环境，不保存为偏好。核心竞态检查采用可控时钟或完成信号；不要用随机 sleep 代替发布权断言。搜索基准的 180ms 防抖与实际首屏延迟口径见 [搜索实施要求](本地搜索引擎实施要求.md)。

## 后续工程边界与参考入口

以下摘自既有工程论证，未在此次精简中重新在线验证。实际接入前核对官方文档、许可和设备结果。

- 三种 WASAPI 模式仍待设备验证；共享低延迟周期须探测，不能固定许诺 96/128 帧或总延迟。USB 麦克风和板载输出即使采样率相同也可能独立时钟漂移，需缓冲／速率匹配及长测；录音、视频、歌词跟随共同音频时基。实时回调避免 IO、解码、分配、锁等待和 UI。
- RAW 通过 `IAudioClient2::SetClientProperties` 的 `AudioClientProperties.Options = AUDCLNT_STREAMOPTIONS_RAW` 设置并处理不支持情况，不存在旧建议中的 `AUDCLNT_STREAMFLAGS_RAW`。RAW 不能强制绕过所有端点 APO／驱动／硬件效果；不用通信类别冒充关闭特效。[低延迟音频](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/low-latency-audio)、[RAW](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/ne-audioclient-audclnt_streamoptions)。
- 原唱／伴唱切换需要独立音轨、明确声道布局或文件，AI 人声分离另行评估。B 站搜索／关联、网页嵌入和原生获取／播放能力分别验证，不能从能打开网页推出可混音、录音、预加载或独占输出。
- Lyrics Helper 是待集成评估项；复用需核对 [库及许可证](https://github.com/WXRIW/Lyricify-Lyrics-Helper)、保留许可／版权／适用 NOTICE 和修改记录，不扩大到 Lyricify 应用、美术或在线词库。歌词来源条件与版本同步单独核验，缺逐字数据不伪造时间。
- 接口参考：[MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API)、[Cover Art Archive](https://musicbrainz.org/doc/Cover_Art_Archive/API)、[LRCLIB](https://lrclib.net/docs)、[Lyrics Helper providers](https://github.com/WXRIW/Lyricify-Lyrics-Helper/blob/master/docs/providers.md)、[Windows 媒体属性](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/medfound/metadata-properties-for-media-files.md)。
- 媒体、录音、个人数据库和缓存不入库；演示素材注明来源与授权。第三方代码许可不替代歌曲、MV、歌词、封面在分发／公开演唱等场景的授权；Git LFS 只解决存储。
